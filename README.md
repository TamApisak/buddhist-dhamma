# เว็บไซต์ชมรมญาติธรรม พุทธธรรมกรรมฐาน

เว็บไซต์เผยแผ่ธรรมะของ **ชมรมญาติธรรม พุทธธรรมกรรมฐาน** (พระกรรมฐานสายหลวงปู่มั่น ภูริทัตโต) จัดทำเป็นเว็บไซต์แบบ static ด้วย HTML, CSS และ JavaScript ล้วน ไม่ต้องติดตั้งโปรแกรม ไม่มีฐานข้อมูล เปิดดูได้ทันที และนำขึ้นโฮสติ้งฟรีได้

เนื้อหาทั้งหมดอยู่ในไฟล์โฟลเดอร์ `content/` แก้ไขด้วยโปรแกรมแก้ไขข้อความทั่วไป (เช่น VS Code, TextEdit แบบ plain text) โดยไม่ต้องเขียนโปรแกรม

---

## 1. เปิดดูเว็บไซต์

**วิธีที่ 1 — เปิดจากไฟล์โดยตรง**
ดับเบิลคลิก `index.html` ใช้งานได้ทุกหน้า รวมถึงการค้นหาและตัวกรอง

**วิธีที่ 2 — เปิดผ่านเซิร์ฟเวอร์ทดสอบ (แนะนำ ใกล้เคียงการใช้งานจริง)**
ต้องมี Node.js ในเครื่อง แล้วรันคำสั่งนี้ในโฟลเดอร์เว็บไซต์

```bash
node tools/serve.js
```

จากนั้นเปิด <http://127.0.0.1:8765/>

## 3. การแก้ไขเนื้อหา

หลังแก้ไขไฟล์ใด ๆ ในโฟลเดอร์ `content/` ให้รีเฟรชหน้าเว็บ หากหน้าแสดงผลว่างเปล่า มักเกิดจากพิมพ์เครื่องหมายผิด (เช่น ลืมเครื่องหมายจุลภาค `,` หรืออัญประกาศ `"`) ตรวจสอบได้ด้วยคำสั่ง

```bash
node --check content/articles.js
```

### 3.1 ข้อมูลชมรมและลิงก์ — `content/site.js`
- `facebookUrl` ลิงก์เพจ Facebook (ใช้ในทุกปุ่ม Facebook ของเว็บไซต์)
- `description` คำอธิบายชมรม (แสดงในส่วนท้ายและ metadata)
- `nav` รายการเมนู
- `topics` หัวข้อสำหรับตัวกรองในคลังธรรมะ (ต้องตรงกับค่า `topic` ในบทความ)
- `showSampleContent` ดูข้อ 4

### 3.2 เพิ่มบทความ — `content/articles.js`
คัดลอกบล็อกบทความหนึ่งบล็อก (ตั้งแต่ `{` ถึง `},`) วางต่อท้ายรายการ แล้วแก้ไขค่า:

| ช่อง | ความหมาย |
|---|---|
| `id` | รหัสบทความภาษาอังกฤษ ไม่ซ้ำ ใช้ในลิงก์ `article.html?id=...` |
| `title` | ชื่อบทความ |
| `topic` | หนึ่งใน `ศีล`, `สมาธิ`, `ปัญญา`, `การเจริญสติ`, `ธรรมะในชีวิตประจำวัน` |
| `author` / `teacher` | ผู้เขียน หรือชื่อครูบาอาจารย์ (ถ้าเป็นคำสอนที่ถอดความ) |
| `source`, `sources` | แหล่งที่มาโดยสรุป และรายการอ้างอิง |
| `date` | วันที่เผยแพร่ ปี ค.ศ. รูปแบบ `YYYY-MM-DD` (เว็บไซต์จะแสดงเป็น พ.ศ. เอง) |
| `excerpt` | คำโปรย 1–2 ประโยค |
| `image` | ที่อยู่รูปภาพ เช่น `assets/images/articles/xxx.jpg` หรือ `null` |
| `sample` | `true` = บทความตัวอย่าง (มีป้ายกำกับ), `false` = บทความจริง |
| `body` | เนื้อหา HTML ในเครื่องหมาย `` ` `` ใช้แท็ก `<p>`, `<h2>`, `<h3>`, `<ul>`, `<ol>`, `<li>`, `<strong>`, `<blockquote>`, `<cite>` |

### 3.3 สื่อธรรมะ — `content/media.js`
- วิดีโอ/เสียงจาก YouTube: ใส่รหัสวิดีโอ 11 ตัวอักษรในช่อง `youtubeId` (เช่น จาก `https://www.youtube.com/watch?v=v2cf3P-Pibk` รหัสคือ `v2cf3P-Pibk`)
- ไฟล์ของชมรมเอง: วางไฟล์ไว้ใน `assets/media/` แล้วใส่ที่อยู่ในช่อง `src` เช่น `assets/media/dhamma-01.mp3`
- ระบุ `speaker`, `duration`, `recorded`, `source` เท่าที่ทราบ
- ระบบจะไม่เล่นสื่ออัตโนมัติ ผู้ชมต้องกดเล่นเองเสมอ

### 3.4 กิจกรรม — `content/activities.js`
- ใส่ `date` (และ `endDate` ถ้ามีหลายวัน) ระบบจะแยก "กำลังจะมาถึง" กับ "ผ่านมาแล้ว" ให้โดยอัตโนมัติเทียบกับวันปัจจุบัน
- ใส่ `link` เป็นลิงก์โพสต์ประกาศหรือรายงานบน Facebook เพื่อให้ผู้ชมดูรายละเอียดเพิ่มเติมได้
- ใส่ `image` เป็นภาพจากกิจกรรม (ต้องเป็นภาพที่ชมรมมีสิทธิ์ใช้)

### 3.5 ครูบาอาจารย์ — `content/teachers.js`
- รายการที่มี `status: "compiled"` และมี `bio` จะมีหน้าประวัติของตนเอง
- รายการที่มี `status: "pending"` จะแสดงเพียงชื่อและวัด พร้อมป้าย "รอข้อมูลประวัติ"
- ทุกประวัติควรระบุ `sources` (ชื่อหนังสือ/เว็บไซต์ พร้อมลิงก์ถ้ามี)

### 3.6 บทความวิชาการ — `content/academic.js`
- คัดลอกรายการเดิมทั้งก้อนแล้วแก้ข้อมูล วางบทความใหม่ล่าสุดไว้บนสุด คำอธิบายแต่ละช่องอยู่ที่หัวไฟล์
- ใส่ชื่อเรื่อง ผู้แต่ง สังกัด วารสาร ปีที่ ฉบับที่ เลขหน้า และวันที่เผยแพร่ ตามหน้าบทความของวารสาร
- `summary` ให้เรียบเรียงสรุปสั้น ๆ ด้วยถ้อยคำของชมรมเอง อย่าคัดลอกบทคัดย่อ เพราะลิขสิทธิ์เป็นของวารสาร
- `pdf` ใช้ลิงก์หน้าเปิดอ่าน (`.../article/view/...`) ไม่ใช่ลิงก์ดาวน์โหลด

## 4. เนื้อหาตัวอย่างและการเผยแพร่จริง

ระหว่างจัดทำ เว็บไซต์แสดงเนื้อหาตัวอย่างพร้อมป้าย **"ตัวอย่าง"** เพื่อให้เห็นรูปแบบ ได้แก่ บทความ 10 เรื่อง สื่อ 2 รายการ และกิจกรรม 3 รายการ

เมื่อพร้อมเผยแพร่จริง:
1. ลบรายการตัวอย่างออก หรือเปลี่ยน `sample` เป็น `false` เฉพาะรายการที่ตรวจทานแล้วและต้องการใช้จริง
2. เปลี่ยน `showSampleContent` ใน `content/site.js` เป็น `false` — รายการที่ยังเป็น `sample: true` จะถูกซ่อนทั้งหมด และหน้าที่ไม่มีเนื้อหาจะแสดงข้อความสถานะว่างภาษาไทยแทน

> บทความตัวอย่างเรียบเรียงจากหลักธรรมทั่วไปพร้อมอ้างอิงพระไตรปิฎก **ไม่มีการแต่งคำพูดของครูบาอาจารย์ท่านใด** แต่ควรให้ผู้รู้ตรวจทานก่อนนำไปใช้จริง

## 5. รูปภาพและโลโก้

วางรูปภาพไว้ใน `assets/images/` (ดูรายละเอียดใน `assets/images/README.md`) ใช้เฉพาะภาพที่ชมรมถ่ายเองหรือได้รับอนุญาตแล้ว

| ประเภท | ขนาดแนะนำ | ตำแหน่งที่ระบุ |
|---|---|---|
| โลโก้ | 512×512 px, PNG พื้นหลังโปร่ง หรือ SVG | `logo` ใน `content/site.js` และเปลี่ยน `logoIsPlaceholder` เป็น `false` |
| ไอคอนแท็บเบราว์เซอร์ | แทนที่ `assets/favicon.svg` | — |
| ภาพบทความ / กิจกรรม | 1200×750 px (สัดส่วน 16:10) | ช่อง `image` ของแต่ละรายการ |
| ภาพครูบาอาจารย์ | 800×1000 px (สัดส่วน 4:5) | ช่อง `image` ใน `content/teachers.js` |
| ภาพในหน้าเกี่ยวกับชมรม | 1200×900 px (สัดส่วน 4:3) | แทนที่กรอบ "ภาพกิจกรรมของชมรม (รอรูปภาพ)" ใน `about.html` ด้วย `<img>` |
| ภาพสำหรับแชร์ลิงก์ (Facebook / LINE) | 1200×630 px สร้างอัตโนมัติ | `assets/og-image.png` ดูข้อ 5.1 |

ตำแหน่งที่ยังไม่มีรูปจะแสดงกรอบภาพชั่วคราวพร้อมข้อความ "รอรูปภาพ" โดยอัตโนมัติ

### 5.1 ภาพที่แสดงเมื่อแชร์ลิงก์

เมื่อโพสต์ลิงก์เว็บไซต์บน Facebook หรือ LINE จะแสดงภาพ `assets/og-image.png` (1200×630 px) ซึ่งมีโลโก้ ชื่อชมรม และคำขวัญ ทุกหน้าใช้ภาพเดียวกัน โดยระบุไว้ในแท็ก `og:image` ส่วนหัวของไฟล์ `.html` แต่ละไฟล์

ภาพนี้สร้างจากแม่แบบ `tools/og-image/template.html` ซึ่งดึงชื่อชมรม คำขวัญ และโลโก้มาจาก `content/site.js` เมื่อเปลี่ยนโลโก้ ชื่อ หรือคำขวัญ ให้สร้างภาพใหม่ด้วยคำสั่งนี้ (ต้องมี Google Chrome ในเครื่องและต่ออินเทอร์เน็ตเพื่อโหลดฟอนต์)

```bash
node tools/make-og-image.js
```

จากนั้น commit และ push ตามข้อ 6.2 Facebook จะจำภาพเดิมไว้ระยะหนึ่ง ให้เปิด <https://developers.facebook.com/tools/debug/> วางลิงก์เว็บไซต์ แล้วกด **Scrape Again** เพื่อให้ดึงภาพใหม่ทันที

## 6. การนำขึ้นเว็บ (เผยแพร่ออนไลน์)

เว็บไซต์เป็นไฟล์ static ทั้งหมด จึงนำขึ้นบริการโฮสติ้งฟรีได้ วิธีที่แนะนำคือ **GitHub Pages** เพราะโฟลเดอร์นี้เตรียมไฟล์ที่จำเป็นไว้ครบแล้ว และทุกครั้งที่แก้ไขเนื้อหาแล้ว push ขึ้น GitHub เว็บไซต์จะอัปเดตเองภายในไม่กี่นาที

ไฟล์ที่เกี่ยวข้องกับการเผยแพร่

- `.github/workflows/deploy-pages.yml` — ขั้นตอนเผยแพร่อัตโนมัติของ GitHub Actions (ตรวจว่าเปิดใช้ Pages แล้ว ตรวจไวยากรณ์ไฟล์ JavaScript แล้วจึงนำขึ้น Pages เฉพาะไฟล์ `.html` ที่โฟลเดอร์หลัก, `.nojekyll`, `sitemap.xml` และโฟลเดอร์ `assets/`, `content/`, `css/`, `js/` ส่วน `tools/`, `design/`, `presentation/`, `.claude/` และ `README.md` จะไม่ถูกเผยแพร่ หากเพิ่มโฟลเดอร์ใหม่ที่ต้องเผยแพร่ ให้เพิ่มชื่อในขั้นตอน *Collect site files* ของไฟล์นี้)
- `404.html` — หน้าภาษาไทยที่แสดงเมื่อผู้ชมเปิดลิงก์ที่ไม่มีอยู่
- `.nojekyll` — บอก GitHub ว่าไม่ต้องประมวลผลไฟล์ด้วย Jekyll (จำเป็นเมื่อเลือกเผยแพร่จาก branch โดยตรงแทน GitHub Actions)
- `.gitignore` — รายการไฟล์ที่ไม่เก็บใน Git เช่น `.DS_Store`, โฟลเดอร์แบบร่าง `design/` และโฟลเดอร์วิดีโอนำเสนอ `presentation/`

### 6.1 GitHub Pages — ทำครั้งแรก

โฟลเดอร์นี้เป็น Git repository แล้ว (branch `main` มี commit แรกอยู่) เหลือเพียงเชื่อมกับ GitHub ทำตามลำดับนี้

1. **สร้าง repository** — สมัครหรือเข้าสู่ระบบ <https://github.com> แล้วกด **New repository**
   - ตั้งชื่อ repository เป็นภาษาอังกฤษ เช่น `dhamma-site` (ชื่อนี้จะเป็นส่วนหนึ่งของที่อยู่เว็บไซต์)
   - เลือก **Public** (GitHub Pages ของบัญชีฟรีใช้ได้กับ repository สาธารณะเท่านั้น)
   - **ไม่ต้อง** ติ๊กเพิ่ม README, .gitignore หรือ license
2. **ส่งไฟล์ขึ้น GitHub** — เปิดเทอร์มินัลที่โฟลเดอร์เว็บไซต์ แล้วรันสองคำสั่งนี้ (แทน `ชื่อผู้ใช้` และ `ชื่อ-repo` ด้วยของจริง)

   ```bash
   git remote add origin https://github.com/ชื่อผู้ใช้/ชื่อ-repo.git
   git push -u origin main
   ```

   เมื่อเทอร์มินัลถาม Username และ Password ช่อง Password ต้องใส่ **Personal access token** ไม่ใช่รหัสผ่านบัญชี (สร้างได้ที่ <https://github.com/settings/tokens> เลือก *Tokens (classic)* และให้สิทธิ์ `repo` โดย token จะแสดงให้เห็นครั้งเดียว ให้คัดลอกเก็บไว้)
3. **เปิดใช้ GitHub Pages** — ในหน้า repository ไปที่ **Settings → Pages** ใต้หัวข้อ *Build and deployment* เลือก **Source: GitHub Actions**

   การ push ครั้งแรกในข้อ 2 จะทำให้ workflow ทำงานทันทีและ **หยุดพร้อมกากบาทสีแดง** เพราะยังไม่ได้เปิดใช้ Pages ถือเป็นเรื่องปกติ (ข้อความในรายการนั้นจะบอกให้มาตั้งค่าข้อนี้)
4. **เผยแพร่** — ไปที่แท็บ **Actions** เปิดรายการ "Deploy to GitHub Pages" ที่ล้มเหลว แล้วกด **Re-run jobs** (หรือเลือก workflow นี้จากรายการด้านซ้ายแล้วกด **Run workflow**) รอจนขึ้นเครื่องหมายถูกสีเขียว เว็บไซต์จะเปิดได้ที่

   `https://ชื่อผู้ใช้.github.io/ชื่อ-repo/`

   (ที่อยู่นี้แสดงไว้ในหน้า Settings → Pages ด้วย)

**ทางเลือกสำหรับผู้ไม่ถนัดบรรทัดคำสั่ง** — ใช้โปรแกรม [GitHub Desktop](https://desktop.github.com) แทนข้อ 1–2 ได้ เพราะโปรแกรมจะสร้าง repository บน GitHub ให้เอง: เข้าสู่ระบบในโปรแกรม เลือก **File → Add Local Repository** ชี้มาที่โฟลเดอร์นี้ กด **Publish repository** ตั้งชื่อ repository เป็นภาษาอังกฤษ เอาเครื่องหมายถูกออกจากช่อง **Keep this code private** (ไม่เช่นนั้น GitHub Pages จะใช้ไม่ได้) แล้วกด **Publish Repository** จากนั้นทำข้อ 3–4 ต่อ

### 6.2 การอัปเดตเว็บไซต์หลังจากนั้น

แก้ไขไฟล์ในโฟลเดอร์ `content/` ตามข้อ 3 แล้วรัน

```bash
git add -A
git commit -m "อัปเดตบทความ"
git push
```

หรือแก้ไขไฟล์โดยตรงบนเว็บ GitHub (เปิดไฟล์ → ไอคอนดินสอ → **Commit changes**) ทั้งสองวิธีจะเผยแพร่อัตโนมัติภายใน 1–3 นาที (ผู้ใช้ GitHub Desktop: พิมพ์คำอธิบายแล้วกด **Commit to main** ตามด้วย **Push origin**)

หากแท็บ Actions ขึ้นเครื่องหมายกากบาทสีแดง ให้กดเข้าไปดูขั้นตอนที่ล้มเหลว หากเป็น *Check JavaScript syntax* จะบอกไฟล์และบรรทัดที่พิมพ์ผิด แก้ไขแล้ว push ใหม่ ระหว่างนั้นเว็บไซต์เดิมยังแสดงผลตามปกติจนกว่าการเผยแพร่ครั้งใหม่จะสำเร็จ

### 6.3 ชื่อโดเมนของชมรมเอง (ถ้ามี)

ที่ **Settings → Pages → Custom domain** ใส่ชื่อโดเมนแล้วกด **Save** จากนั้นตั้งค่า DNS ตามคำแนะนำของ GitHub (<https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site>) เมื่อเผยแพร่ผ่าน GitHub Actions ไม่ต้องมีไฟล์ `CNAME` ใน repository (GitHub จะไม่สร้างให้ และถ้ามีก็จะไม่ถูกใช้) ส่วนใบรับรอง HTTPS GitHub จะออกให้เอง ซึ่งอาจใช้เวลาถึง 24 ชั่วโมง เมื่อตัวเลือกพร้อมแล้วควรติ๊ก **Enforce HTTPS**

หลังเปลี่ยนชื่อโดเมน ให้ค้นหาข้อความ `https://tamapisak.github.io/buddhist-dhamma/` ในไฟล์ `.html` ทุกไฟล์ (แท็ก `og:image`) และใน `sitemap.xml` แล้วแทนที่ด้วยที่อยู่ใหม่ เช่น `https://ชื่อโดเมน/` เพราะ Facebook ต้องใช้ที่อยู่ภาพแบบเต็ม

### 6.4 บริการอื่น

- **Netlify / Cloudflare Pages** — เชื่อมกับ repository บน GitHub (ไม่ต้องใส่ build command และ publish directory คือโฟลเดอร์หลัก `/`) หรือลากโฟลเดอร์ทั้งหมดไปวางในหน้า Deploy (ไฟล์ส่วนเกินเช่น `tools/` จะถูกอัปโหลดไปด้วย แต่ไม่กระทบการแสดงผล)
- **โฮสติ้งทั่วไป** — อัปโหลดทุกไฟล์และโฟลเดอร์ (ยกเว้น `.git/`, `.github/`, `.claude/`, `design/` และ `tools/`) ไปยังโฟลเดอร์ `public_html` ผ่าน FTP

เว็บไซต์ใช้ลิงก์แบบสัมพัทธ์ทั้งหมด จึงทำงานได้ทั้งที่โดเมนหลักและที่อยู่แบบมีโฟลเดอร์ย่อย เช่น `.../ชื่อ-repo/` ทดสอบแบบหลังในเครื่องได้ด้วย `node tools/serve.js 8766 --prefix ชื่อ-repo` แล้วเปิด <http://127.0.0.1:8766/ชื่อ-repo/>

## 8. หมายเหตุทางเทคนิค

- ตัวอักษร Sarabun และ Noto Serif Thai โหลดจาก Google Fonts (ต้องเชื่อมต่ออินเทอร์เน็ต) หากต้องการให้ทำงานแบบออฟไลน์สมบูรณ์ ให้ดาวน์โหลดฟอนต์มาไว้ใน `assets/fonts/` แล้วแก้ `@font-face` ใน `css/style.css`
- ภาพปกวิดีโอโหลดจาก `i.ytimg.com` และวิดีโอฝังผ่าน `youtube-nocookie.com` (ไม่เล่นอัตโนมัติ)
- ขนาดตัวอักษรที่ผู้ใช้เลือก (ก− / ก+) จดจำไว้ในเบราว์เซอร์ของผู้ใช้ (localStorage)
- รองรับเบราว์เซอร์สมัยใหม่ทั้งบนคอมพิวเตอร์และโทรศัพท์ (Chrome, Safari, Firefox, Edge)
- เว็บไซต์ไม่มีระบบรับบริจาค ไม่มีแบบฟอร์มส่งข้อมูล และไม่เก็บข้อมูลส่วนบุคคลของผู้เข้าชม
